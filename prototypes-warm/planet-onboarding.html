WARM · 星球路由方案 · PROTOTYPE

首次进入「选一个星球」——路径设计与可交互原型

补上缺失的一环：用户第一次点进星球 Tab 时，应该先看到所有社区、由他选一个作为主星球；选定后写入 user.main_planet_id，之后每次进入直接落在主星球。同时把「切换」从跳页改成半屏弹层，就地生效不丢上下文。

核心结论

不新建「 onboarding 页面」，而是把已有的 planet-list 改造出两种形态（首次引导态 / 常驻管理态），再加一个半屏切换器组件替代现有的跳页切换。理由：列表数据源、设为常驻接口、介绍页、下单页全部已存在，缺的是「什么时候让用户选」和「切换时能不能不跳页」这两个决策点。原路径「点 Tab 直接落到配置 primary 星球」保持不变，作为游客与兜底路径。

三、什么时候弹选择页（判定表）

只在「星球 Tab 的第一次进入」弹一次，且必须已登录。任何一条不满足都直接走原路径，避免把用户拦在门口。

序条件行为理由
1已登录 且 GET /main 返回 userSet=false 且本地无 main_planet_id弹选择页
redirectTo?mode=pick		这就是「首次进入且没选过」的唯一判据
2已登录 且 userSet=true直达主星球选过了就不再打扰
3未登录直达配置 primary开屏/进 Tab 拦登录会被审核驳回
4选择页已用「先逛逛」退出过直达 + 顶部一次性提示条看过一次引导就不再拦，改用非阻断提示
5主星球被运营停用（enabled=false）直达配置 primary + toastresolveMainPlanet 已回落，端上要提示「原星球已停用」
6只有 1 个启用社区直达，不弹没得选就不该让用户「选」
7GET /main 网络失败用本地缓存；无缓存则直达配置 primary网络问题不该导致白屏或卡在引导页
8用户已加入 ≥1 个星球但没设主星球直达主星球（配置 primary）这种情况只可能在老版本产生，不追溯弹引导，避免存量用户被打扰

四、可交互原型

左边调状态，右边点。所有按钮都能点，状态是真实联动的：加入后星球变「已加入」、设为常驻后主星球立刻换人、游客模式下所有写操作会弹登录层。默认停在「首次进入 + 已登录 + 未选过」。

五、组件与接口契约

🧩 新增组件 planet-switch-sheet

半屏弹层，替代现有跳页切换。三处接入：

  • components/dsl-planet-hero 的 onSwitch
  • pkg-content/planet-feed 的 onSwitchPlanet
  • components/dsl-warm-block 的 onPickMainTap

props：list（社区数组）、currentId
events：change（已加入的切主星球，携带 planetId）、intro（未加入的进介绍页）、close

硬约束：切换成功后宿主必须刷新自己的数据源。星球 Tab 刷新 warm，首页刷新 warm.primaryPlanetId / primaryOnly，动态流页重拉 /planet/feed。只改一处会出现三端不一致。

🔧 改造 planet-list

加参数 mode=pick|first，只影响文案与主按钮，不新增接口。

  • pick：标题「选一个你的星球」，副标「以后可以随时换」，卡上主按钮为「加入星球」或「设为常驻」，底部固定「先逛逛」+ 一行小字
  • first（缺省）：保持现状「我加入的星球」，无底部栏

踩坑提示：onLoad 里任何 xxx() 抛错都会中断后续，配置拉取必须排最前；mainPlanetId 回落顺序是 接口 → 缓存 → 列表里 primary → 第一条，四级兜底不能省。

🔐 登录层补 intent

AuthUtil.requireLoginForAction(action, {silent}) 现在不登录直接 return，用户登录完得自己再点一次。

加 intent：
{ type:'setMain'|'join', planetId, from:'picker'|'sheet'|'home' }
登录成功后由调用页读取并续跑，避免「登录完还要再点一次加入」。

不要把选择页做成必须登录才能看——浏览路径全程不拦。

六、实施优先级

级别事项端说明
P0 星球 Tab onShow 加首次判定 + redirectTo?mode=pick 小程序 路径 A 的入口。判定条件严格按第三节第 1 条（已登录 + userSet=false + 无缓存）
P0 planet-list 加 mode=pick 形态与「先逛逛」 小程序 不改接口、不改数据结构，只换文案与主按钮
P0 兜底：主星球停用提示、接口失败用缓存、只剩 1 社区不弹 小程序 这三条不做，引导页会变成「进不去也出不来」的坑
P1 planet-switch-sheet 组件 + 三处接入 小程序 解决「切换要跳页、跳页丢上下文」。三处宿主刷新逻辑必须同时上
P1 登录层 intent 续跑 小程序 已有 login-sheet 组件，不用新建
P2 「选星球」分享落地页：带 planetId 参数进小程序直接落该星球的介绍页 小程序 增长位，先不做。scene 有 32 字符上限，别直接拼 id，要存短 ID
P2 后台社区配置加「引导页排序 / 是否进引导页」开关 后台 复用 mp_planet 配置的 sortOrder 与 enabled，不要新造字段
口径对齐：主社区 id 为 warm-main（defaultCommunities() 的 primary），另有 warm-read / warm-write；主星球默认值取 planet_config.communities[].primary，前端不硬编码。社区清单以 GET /api/v1/mp/planet/communities 返回为准，本原型中的星球文案仅为示意。
