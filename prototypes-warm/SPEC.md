# 暖阁 · 小程序开发交付说明

> 配套原型：`prototypes-warm/index.html`（总览页，可点击互跳）
> 本文档是开发前的准备材料，描述目标形态与约束，**不涉及对现有 `miniapp/` `backend/` 代码的改动**。

---

## 一、产品定位与阶段

暖色系内容平台，博主与粉丝之间的连接载体。

| 阶段 | 内容生产 | 用户权限 | 说明 |
|---|---|---|---|
| 阶段一（当前） | 仅运营团队 | 读 / 评论 / 收藏 / 星球提问 / 打卡 / 购买 | 署名收敛为主理人、编辑部、特约作者三类 |
| 阶段二 | 开放 UGC | 增加投稿与发布 | 页面形态已预留，只需开权限 + 上发布器 + 开审核队列 |

数据结构从第一天起就按 UGC 设计（作者表、内容表、审核状态），阶段切换不需要改版。

## 四、关键字段定义

### 4.1 资料与试读（`resource`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `file_type` | enum | pdf / xlsx / docx / zip |
| `page_count` | int | 总页数，用于计算试读比例 |
| `visibility` | enum | public / member / column_buyer / planet_member |
| `preview_mode` | enum | `none` 完全不可见 / `first_page` 仅首页 / `pages` 前 N 页 / `percent` 前 N% / `full` 全部 |
| `preview_value` | int | 配合 pages / percent 使用 |
| `allow_forward` | bool | 是否允许转发保存到微信 |
| `watermark` | bool | 是否叠加昵称 + 手机号后四位 |

**安全约束（重要）**：试读裁切必须在服务端完成后再下发，不可下发完整文件由前端遮挡，否则可被抓包绕过。

### 4.2 商品（`goods`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `goods_type` | enum | `ebook` / `resource_pack` / `column` / `membership` / `physical` |
| `price` / `member_price` | int | 单位：分。避免浮点误差 |
| `member_free` | bool | 会员是否免费 |
| `delivery_mode` | enum | `auto`（支付回调自动开通）/ `manual` / `redeem_code` |
| `refund_policy` | enum | `none` / `before_read` / `seven_days` |
| `preview_chapters` | int | 免费试读章数，与资料库共用 preview 逻辑 |
| `publish_at` | datetime | 定时上架 |

仅当 `goods_type = physical` 时才出现收货地址、运费、物流模板；虚拟商品全部隐藏这些字段。

### 4.3 会员权益（`member_benefit`）

做成开关组合存配置表，改动即时生效不发版：全站长文免费读、资料库全解锁、商城折扣（数值）、赠送星球天数（数值）、身份角标、到期提醒天数。

### 4.4 内容与审核（`content`）

| 字段 | 说明 |
|---|---|
| `content_type` | article / note / planet_post / comment |
| `author_role` | owner 主理人 / editor 编辑部 / contributor 特约 / user 普通用户 |
| `audit_status` | pending / machine_passed / approved / rejected / auto_blocked |
| `visibility` | public / member_only / removed |

**下架不等于收回权限**：内容下架后，此前已购买的用户必须仍可在「我的 - 已购内容」阅读，这是虚拟商品的合规底线。

### 4.5 邀请关系（`invite`）

分享携带的邀请信息通过 `scene` 参数在新用户首次授权时落库。小程序码 `scene` 上限 32 字符，不要直接拼接用户 ID + 内容 ID，应存短 ID 再查表。

## 四之二、Agent 与知识库（阶段一：仅后台）

原型：`admin-agent.html`

### 设计原则

Agent 在阶段一**不向用户开放**，只作为运营团队的生产工具，小程序端不出现任何入口。数据结构与展示形态提前预留，阶段二开放时不需要改版——与 UGC 的阶段设计一致。

四个概念组合出一个可控的 Agent：

| 概念 | 作用 | 字段 |
|---|---|---|
| 人格身份 Persona | 决定产出物在前端的署名 | `persona_id`，复用作者矩阵，不新建机器人账号 |
| 可读知识库 | 决定它知道什么、能说多少 | `knowledge_base_ids[]` + 每项 `cite_policy` |
| 触发场景 Scope | 决定它在哪里被调用 | `trigger_scopes[]`，阶段一全部限定 `backend` |
| 发布卡点 | 决定能否直接对外 | `require_human_review`，强制为 true |

### 三个预置 Agent

| Agent | 身份 | 可读知识库 | 触发场景 |
|---|---|---|---|
| 一稿三用改写 | 跟随原文作者 | 站内长文、品牌语气库 | 编辑器辅助按钮 |
| 知识检索问答 | 暖阁编辑部 | 站内长文、星球沉淀、资料库 | 后台问答、客服辅助 |
| 主理人分身 | 墨白 · 主理人 | 墨白作品、星球问答（排除会员专享原文） | 星球提问、定时任务 |

### 知识库（`knowledge_base`）

| 字段 | 说明 |
|---|---|
| `source_type` | `sync` 站内自动同步 / `upload` / `crawl` / `mixed` |
| `sync_filter` | 同步条件，如「内容类型=长文 且 可见性=member_only 且 已发布」。命中即入库，下架即移除，无需人工维护 |
| `cite_policy` | `full` 完整引用 / `summary` 仅摘要+引导购买 / `none` 不可引用 |
| `chunk_size` / `chunk_overlap` | 切片设置。长文按小标题切；星球问答以「一问一答」为最小单元，不跨条切 |
| `index_status` | 索引进度 |

一个知识库可被多个 Agent 引用；Agent 关联时可**再收紧**引用策略，不可放宽。

### 付费墙防护（最关键的一条）

引用策略必须在**服务端检索阶段**生效：标记为 `summary` 的条目，检索时只返回摘要向量与结论字段，**原文根本不进入模型上下文**。不要依赖提示词约束模型「不要复述原文」，那不可靠。否则 Agent 会成为绕过全部付费墙的后门。

### 已确认的三个决策

1. **不标注「AI 辅助」**：产出视为团队自产，前端展示逻辑无需改动，署名沿用作者矩阵。
2. **付费内容默认「仅摘要 + 引导购买」**：既解决用户问题又不洗稿，顺带成为转化入口。
3. **一律进草稿箱，人工确认后才能发布**：该卡点不可关闭。

### 其他约束

- AI 产出同样要过 `security.msgSecCheck` 再发布。
- 记录每条产出的模型、提示词版本、引用来源、确认人，便于追溯。
- 设置日调用次数与日成本上限，超出暂停并告警。
- 草稿超时（建议 48 小时）未处理自动废弃，避免堆积。
- **采用率**是衡量 Agent 是否好用的核心指标，应在后台常驻展示。

## 五、微信侧技术约束

这几条直接决定交互形态，设计时已按此处理：

1. **没有「下载到本地」**。附件只能 `wx.downloadFile` 取临时路径后 `wx.openDocument` 在线预览；用户留存靠「转发给朋友」发给自己。所有「下载」文案已改为「预览」。
2. **朋友圈不能直接转发小程序**，只能生成海报图。分享面板已对两条路径做了区分标注。
3. **支付回调必须幂等**。同一 `out_trade_no` 重复回调只开通一次权限，并处理「已扣款未开通」的补偿查询。
4. **登录合规（2022 年后规则）**。
   - **时机**：浏览公开内容不拦截；仅在收藏、评论、购买、进星球等动作时唤起登录弹层。开屏强制登录容易被审核驳回。
   - **身份**：用 `wx.login` 换 openid 建立会话，不依赖旧版「微信一键拿资料」。
   - **头像昵称**：`getUserProfile` 已收回真实资料，改用头像昵称填写能力（`chooseAvatar` + `input type="nickname"`）。
   - **手机号**：仅在业务需要时用 `getPhoneNumber`；须用户主动点击；拒绝后提供显著「暂不登录」，不得反复强求；非个人已认证主体才可用该能力。
   - **隐私**：调用隐私接口前，须先用 `agreePrivacyAuthorization` 同步用户已同意隐私政策。
   - 原型见 `states.html` ①；实现对齐现网 `miniapp/components/login-sheet`。
5. **订阅消息需用户主动触发授权**，且为一次性。会员到期提醒的授权入口建议放在支付成功页。
6. **虚拟支付合规**：iOS 端虚拟商品支付受微信规则限制，上线前需确认类目与支付方案，必要时 iOS 走「已在其他渠道购买后同步权限」的形态。

## 七、建议的开发顺序

1. **权限与支付**：会员体系、商品表、微信支付回调与幂等、虚拟商品权限开通。这是最容易出问题也最难返工的部分。
2. **内容与试读**：内容表、资料表、服务端试读裁切、付费墙。
3. **主框架五页**：Tab 骨架 + 首页 / 列表 / 详情。
4. **星球与互动**：动态流、提问、评论、打卡。
5. **分享与邀请**：转发卡片、海报生成、邀请关系落库。
6. **社群与客服**：客服会话、企微跳转、群码管理。
7. **异常态补全**：六种状态贯穿所有页面，建议做成公共组件而非逐页实现。
8. **UGC 阶段二**：发布器 + 审核队列（可延后）。
