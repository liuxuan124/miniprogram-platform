维度现状根因
命名 同一概念最多 5 种叫法；小程序端「知识库」= 后台「商品」，后台 AI 又有另一个「知识库」；User 与 MiniProgramUser 双实体映射同一张 mp_user；菜单/面包屑/页面标题三处不一致 11 处；父子路由同名 4 组 无术语表，各期功能各自命名

视觉 两套 token 互相冲突（主色 #002FA7 而 hover #1458d9 非同色族）；10 种圆角并存；.surface-card 定义了但 0 页使用 设计 token 有定义、无强制约束

数据表另有遗留污染：sys_user、`user`、mp_booking_* 三套废表，其中 mp_booking_* 有表无实体。

1.1　撞名处理（已定）

小程序端 Tab「知识库」（实为商品列表）保留原名不动，避免影响 C 端已形成的认知与已上线版本。撞名从后台一侧解决：AI 相关的「知识库管理」全部改称「AI 语料库」，涉及菜单名、路由 meta、页面标题与 ai/knowledge/index.vue 内文案。代码层 knowledge 标识符不变，仅改展示文案。

2.1　主题收口

删除 admin/src/styles/tokens.css，只保留 admin/src/assets/styles/theme.css：主色 9 阶、冷中性 8 阶、语义色三组带 soft 底、字号 4 档、间距 6 档、圆角只留 6/8/12 三档（删掉现有 10 种），Element Plus 变量全部桥接到上述令牌。

2.2　禁止再写死样式

这条是关键。 不加约束，半年后必然回到现在的状态——现有 484 个色值就是这么积累的。

新增 stylelint 规则对 admin/src/views/** 生效：禁止 hex / rgb 字面量（只允许 var(--*)）、禁止裸 font-size: Npx、border-radius 仅允许三档令牌。规则先只对新增或改动的文件生效（lint-staged），不做全量强制，避免阻塞开发。

2.3　五个布局组件

组件职责硬约束
PageHeader标题 / 描述 / 右侧操作区全页唯一 primary 按钮位
FilterBar筛选项 + 重置/查询，超过 4 项自动折叠查询按钮不得为 primary
PageCard卡片容器只有 1 档边框、1 档圆角
DataTable分页 / 加载 / 空态 / 批量栏 / 导出行内操作统一 text 按钮
FormSection表单分节 + 完成度节标题序号自动生成

配套：指标区改开放式横排（如原型中的 148 / 23 / 31 / 12），不再人人一张卡。

2.4　试点顺序

工作台 → 内容列表 → 星球配置。三页验收通过后，按「列表页批量替换 → 表单页逐个替换」铺开。

03命名与信息架构第 2 期

3.1　目标信息架构（6 组，按运营任务划分）

工作台
小程序      总览 · 页面 · 外观与导航 · 发布
内容运营    内容 · 分类 · 评论 · 资料文件 · 素材 · 问答 · 表单
会员与用户  用户 · 会员等级 · 积分 · 星球
交易        商品 · 订单 · 退款 · 优惠券

系统        基础设置 · 微信配置 · 存储 · 权限与账号 · 操作日志

变动要点：素材与资料文件从「系统」移入「内容运营」；增长与统计两页合并为「经营分析」；AI 从「经营」独立；当前 20+ 条有路由无菜单的页面（统计概览、AI 对话、内容分类、评论、会员等级、积分、微信/存储/日志/账号）全部接入菜单或明确收进上级页 Tab。

不保留兼容 redirect，直接改干净。

因不留兼容，迁移需同步改：router/index.ts、Sidebar.vue 的 path/activePrefix、各页面内硬编码的 router.push、CommandPalette 搜索项、stores/feature-modules.ts 里的跳转。改完全量 grep 旧路径字面量确认无残留。

同期清理：删除 4 个无路由的 orphan 页面（views/commerce/index.vue、views/marketing/index.vue、views/form-activity/index.vue、views/settings/index.vue）；修复 page-builder/overview.vue:227 跳向不存在路由 /page-builder/pages 的死链。

3.3　三处标题强制对齐

Sidebar 菜单名 = 叶子路由 meta.title = 页面 PageHeader 标题。父级路由 meta 只用于分组且不得与子项同名——现有「内容管理/内容管理」「活动管理/活动管理」「优惠券/优惠券」「系统设置/系统设置」四组重名会直接产生重复面包屑。

3.4　后端命名（低风险部分同期做）

  • /api/v1/mp/member 改为复数 /mp/members
  • 裸挂在 /api/v1/mp 下的 4 个 Controller（growth / upload / form-appointment / product-review）收进各自资源前缀
  • 合并 User / MiniProgramUser 双实体为一个
  • 清理 sys_user、`user`、mp_booking_*：先改名加 _deprecated_ 前缀观察一个版本再删

04流程重构第 3 期

按影响排序的 8 项，前四项为 P0。

P0-1

小程序发布：5 套概念砍到 3 个

现状「上线 / 保存草稿 / 保存版本 / 还原点 / 上传代码」并存，运营经常误进「版本」页。统一为三态：草稿 → 已上线 → 历史版本。

外观页的「草稿记录/还原点」与页面的「历史版本」合并为同一概念；「保存版本」改叫「存档当前状态」并与「上线」同区呈现、文案写明区别；「上传代码」独立为「小程序发版」明确是微信侧动作；「导入/查看 DSL」收进高级抽屉默认不可见。

P0-2

会员权益：文本框改勾选器

member/level.vue 的「权益描述」是自由文本，后端只认 MemberBenefitCodes 里的固定码——运营填「95折」完全不生效。

改为权益码多选 + 参数输入（折扣率、积分倍率），描述文案由所选权益自动生成，等级列表显示「已生效 / 仅展示」标记。原有自由文本迁移进 benefits_legacy_note 保留展示，不丢数据。

P0-3

会员体系配置向导（跨 5 页 → 1 页）

在 /member/planet 增加五步向导：等级 → 套餐 → 星球可见范围 → 内容标记 → 模块开关，同页完成，每步显示当前状态与跳转。

同时修掉三个断点：商品分类允许勾选 membership（product/category.vue:116）；商品列表筛选加「会员套餐」（product/index.vue:46）；删掉从星球跳转时硬编码 category_id = 2（product/edit.vue:1467），改为按 allowed_product_types 自动匹配。

P0-4

内容编辑加防丢失

商品编辑和装修器都有自动保存 + 离开提醒，内容编辑（15+ 字段）两者都没有，且保存后强制跳回列表。补齐 5s debounce 自动保存 + beforeunload + 路由守卫；保存后留在原页并提示，「返回列表」作为显式操作。

P1-5

内容分类的隐藏依赖

分类不「发布到顶栏」就不出现在发文下拉里，新手会卡住。改为发文下拉显示全部分类，未发布的标注「未上架，发布后 C 端不可见」并提供一键上架。分类双入口保留列表内弹窗为主，独立页改为跳转。

P1-6

功能开关一致性

order 开关目前完全无效（订单菜单跟 product 走），comment 有开关有路由但无菜单。逐个校准 12 个开关的「菜单可见性 + 小程序表现 + 后端 Guard」三方一致，并统一前端 store 与 basic.vue UI 的默认值（现在商品一个默认开、一个默认关）。

P1-7

评论审核接入内容流

内容列表每行增加评论数与「审核」直达链接，评论审核页加入「内容运营」菜单。

P2-8

系统设置拆分

basic.vue 2342 行承担 5 个 Tab（基础 / 模块 / 物流 / 权限 / 订阅），拆为 /system/basic、/system/modules、/system/logistics、/system/roles、/system/subscribe 五页。模块开关切换增加二次确认（当前切换即保存，误点直接影响 C 端）。

05分享功能升级第 4 期

全系统最弱环节。地基已有：全站分享兜底（好友 + 朋友圈）、16 页增强分享、inviterId 归因链、后端邀请绑定接口与积分任务。

5.1　三处断裂

断裂点具体表现证据
配置不生效 miniappShareTitle / miniappShareImage 与页面 DSL 的 share_title / share_image 后台都能配，小程序运行时不读，仍用硬编码标题表 miniapp/utils/share.js:37-49
归因漏在主力页 内容 / 商品 / 动态 / 问答等 6 个详情页自定义了 onShareAppMessage 但绕过 buildSharePath，分享出去不带 inviterId——而这几页正是分享量最大的 content-detail.js:325 等 6 处
无增长产品化 无小程序码、无分享海报、无邀请页；营销「邀请好友」是占位按钮；reward_status 建表后永远 pending；埋点无 share 事件，看板无分享数据 marketing/index.vue:50、V46:87

5.2　P0 接线（工作量小，收益立刻可见）

改动位置
share.js 优先读后台配置，硬编码表降为最后兜底miniapp/utils/share.js:19-49
DSL 页把 share_title / share_image 写入页面分享配置miniapp/utils/render.js:328（已解析，补 setData）
6 个详情页自定义分享改为走 buildSharePath见 5.1 第 2 行各页
补 share 埋点事件（分享发起 + 分享落地）复用 /api/v1/mp/events
后台分享配置从 basic.vue 抽成独立「分享设置」新页 /system/share

兜底链设计：后台配置 → 实体字段 → 硬编码，任一层缺失不报错，确保不影响已上线版本。

5.3　P1 产品化

  • 小程序码生成：后端接 getwxacodeunlimit，支持带 scene 的渠道码 / 邀请码；后台可为页面、商品、星球一键生成并下载
  • 分享海报：小程序侧 canvas 合成（封面 + 标题 + 小程序码 + 邀请人昵称），详情页加「生成海报」
  • 邀请页：新增 pkg-user/invite，展示邀请码、已邀人数、奖励进度；后台占位页替换为真实配置（奖励类型、额度、上限）
  • 统一 scene 路由器：现在 inviterId、sourceChannel、内容 ID 三处各自解析 scene，合并为一个入口

5.4　P2 闭环与看板

  • 邀请奖励真正发放：reward_status 状态机（pending → granted → 失败原因），支持积分 / 优惠券 / 会员天数三种奖励
  • 被邀请人也给奖励（现在只有邀请人拿 10 积分）
  • 分享看板：分享次数、分享带来访问 / 注册 / 付费，按页面与渠道拆分；接入「经营分析」漏斗补 share 步骤

07风险与规避

风险影响规避
路由不留兼容，改漏一处即白屏高迁移后全量 grep 旧路径字面量；逐路由点击走查；router 加 404 兜底日志
数据表清理误删线上数据高只改名加 _deprecated_ 前缀，观察一个版本再删；操作前 dump 备份
主题令牌替换导致页面样式错乱中先只新增 theme.css 并保留旧变量别名，试点三页验证后再删旧文件
stylelint 规则阻塞开发中规则先只对新增 / 改动文件生效（lint-staged），不做全量强制
分享改造影响已上线小程序中分享配置读取做兜底链，任一层缺失不报错
会员权益改勾选器，已有自由文本丢失中迁移脚本把原文本存入 benefits_legacy_note 保留展示
删 4 个 orphan 页面误删仍被引用的低删前 grep 组件名与路径确认零引用

08执行约定

  • 每期完成后给出改动清单 + 本地构建验证结果，确认后再部署
  • 每期内部按「地基 → 试点 → 铺开」推进，试点不通过不铺开
  • 不主动 commit，改动留在工作区供 review
  • 涉及线上数据库变更（第 5 期表清理）单独提方案确认，不随期执行
