内容管理 Agent：设计方案

把 AI 从「客服问答」扩展为「能在内容库里干活的员工」· 2026-08-22

核心主张：它是个「员工」，不是「聊天框」——所以设计的重点不是提示词，是授权边界和审核动线

你现在内容库里 6 篇导入的文章，状态全是草稿 / 未分类。这就是 Agent 最该干的活：分类、打标签、写摘要、查排版问题、补 SEO。这些活单调、重复、有明确对错，正好是 AI 擅长而人不愿意干的。

但一个能改内容库的 AI，做错了代价也是真实的——分类错了影响频道展示，改了正文可能把原意改没，误发布就直接到用户面前。所以整套设计围绕三件事展开：它能做什么（任务清单）、它能改到什么程度（三层授权）、改完谁点头（审核动线）。

好消息是底子现成：已有的 mp_agent_config 有模型配置、系统提示词、知识库、版本管理和连通性测试，调用走的是 OpenAI 兼容的 /chat/completions。这次是在它上面加一个角色维度和一套任务系统，不是从零建。

一、三层授权模型（整个设计的骨架）

每个任务单独配授权等级，默认全部 L1。跑顺了再逐个提权——这个顺序不要反。

等级能做什么典型任务风险
L1 只读只产出建议和问题清单，不写任何字段排版质检、合规预检、选题建议、效果复盘几乎为零，可以放心开
L2 改草稿可写草稿状态内容的元数据字段：categoryId / tags / summary / seoTitle / seoDescription / coverImage / layoutTheme；正文改动必须走 diff 审核自动分类、打标签、生成摘要与 SEO、排版规范化可控，改错了在草稿里，且可回滚
L3 可发布可改 status / isPinned / isRecommended / scheduledAt，即能让内容出现在用户面前定时发布、自动上架、推荐位编排高。建议前三个月不要开

再叠一层禁改清单（无论什么等级都不许动）：商品价格与优惠券相关文案、订单/支付说明、法律与资质声明、已发布内容的正文。这类内容改错的后果不是"不好看"，是纠纷。

二、任务清单

按你当前最痛的顺序排。每条都标了建议的授权等级和是否需要调模型——规则能解决的绝不调模型，又快又准还省钱。

A 组 · 入库体检（直接对应你刚遇到的排版问题）

#任务做什么授权调模型
A1导入质检扫描正文，报出：图片无 src（图片丢失）、开头疑似被裁、连续空段落、超长段落（>500 字无分段）、正文 h1 与标题重复、图片指向 localhost 或外域、缺封面、正文过短L1否（正则）
A2排版规范化统一段间距与字号、清理空 <section> 与冗余 span、图片补 alt、标题层级归一（h1→h2）、中英文间距、全半角标点统一L2否（规则）+ 可选模型润色
A3合规预检调已接入的 msgSecCheck + 违禁词库（绝对化用语「最」「第一」、医疗功效、金融收益承诺、竞品攻击）L1否 + 模型兜底判语境

A1 建议做成导入完成后自动触发：导完 187 篇，直接给一张"32 篇有问题"的清单，比人工一篇篇点开看强得多。

B 组 · 元数据补全（你截图里 6 篇全是「未分类」）

#任务做什么授权调模型
B1自动分类读现有分类树 + 正文，给出分类 + 置信度。置信度低于阈值不自动填，转人工L2是
B2自动打标签优先复用已有标签库，确实没有再建新标签，单篇上限 5 个——不加这条约束标签会爆炸L2是
B3摘要与 SEO生成 summary（列表页用）、seoTitle、seoDescription、以及三种长度的分享文案（微信卡片 / 朋友圈 / 社群）L2是
B4封面建议从正文图里挑最合适的一张作封面；无图时提示需人工补L2是（多模态）或规则取首图

C 组 · 内容再生产

#任务做什么授权
C1一稿多态长文 → 笔记（小红书风多图短文）/ 动态 / 朋友圈文案 / 口播稿。一篇内容吃干榨净，这是投产比最高的一条L2 落草稿
C2选题与初稿基于知识库 + 搜索无结果词 + 热搜词生成选题列表；选定后写初稿。永远只落草稿L2
C3旧文焕新把半年前的文章按新政策更新，明确标注哪些地方需要人工核实（政策类内容 AI 最容易编）L1 出建议

C2 里"搜索无结果词"这个数据源值得强调——用户搜了但没搜到的词，就是最诚实的选题清单。mp_search_log 和 /mp/search/insights 已经在采集了，直接可用。

D 组 · 运营闭环

#任务做什么授权
D1商品挂载建议基于正文语义推荐挂哪些商品（mp_content_product 表已建好）L2
D2内容效果复盘结合 mp_analytics_event，每周给一份：哪类内容阅读完成率高、哪些带来了加购、下周选题建议L1
D3发布排期建议结合历史阅读时段分布，建议每篇的发布时间（配合已有的 scheduledAt 定时发布）L1 → 熟了给 L3

三、交互形态：任务卡片，不是对话框

这是我认为最关键的产品判断——不要做成一个聊天窗口。运营要处理的是 187 篇内容，不是跟 AI 聊天。

动线：

内容列表 → 勾选若干篇（或"全选草稿"）
   → 点「交给 Agent」→ 选任务（可多选：分类 + 标签 + 摘要）
   → 生成任务，后台异步跑，列表页顶部显示进度条
   → 完成后进「待审核」→ 逐条 diff 或批量确认
   → 采纳 / 部分采纳 / 驳回（驳回可填原因，作为下次的反馈）

两种审核视图：

· 批量确认视图——元数据类任务用这个。6 篇文章的分类建议一屏列完，每行「标题 / 建议分类 / 置信度 / ✓✗」，全部采纳一键搞定。

· 逐条 diff 视图——正文改动类任务必须用这个。左原文右建议，改动高亮，支持单独接受某一处。

另外保留一个对话入口做兜底：选中一篇 → 「让 Agent 处理」→ 自由输入"帮我把这篇改成小红书风格，控制在 300 字"。任务化覆盖 90% 的重复劳动，对话覆盖剩下的长尾。

四、必须有的安全阀

机制怎么做为什么
全量留痕 + 回滚每次采纳生成一条内容版本快照，可一键还原到 Agent 改动前没有回滚就不敢授权，这是提权的前提
置信度阈值分类/标签低于阈值（如 0.7）不自动填，强制转人工AI 不确定时最容易一本正经地胡说
成本闸门单篇 token 上限、日预算上限、超支自动停机并告警批量任务 × 长文 = 账单很容易失控
幂等同一篇 + 同一任务 + 内容未变 → 直接复用上次结果，不重复调模型省钱，也避免同一篇给出两次不同建议
降级模型不可用时，规则类任务（A1/A2/A3 的规则部分）照常跑体检和规范化不该依赖模型可用性
审核时效待审核超过 7 天提醒，30 天自动作废避免堆积成"永远看不完的建议"
禁改清单价格、优惠券、订单、法律声明、已发布正文——硬编码拦截这类改错是纠纷不是瑕疵

五、技术落地

复用现有的东西

· mp_agent_config：加一个 role 字段（service=现有客服 / content_ops=内容员工），每个角色一套 system_prompt 与模型参数，其余字段与版本管理机制不变。

· 知识库 mp_agent_knowledge：内容员工挂"品牌调性说明、行业术语表、违禁词库、往期优质文章"，用来约束文风。

· 模型调用：沿用 AgentConfigServiceImpl 里的 /chat/completions 封装与 ping 测试。

· 异步执行：直接复用公众号导入改造那套线程池 + Redis 进度（见《公众号内容导入改造方案》），一套机制两处用，别再造一个。

新增两张表 + 权限点

mp_agent_task          -- 任务：id / role / taskType / scope(内容ID列表) /
                          status / total / processed / operatorId / costTokens / createdAt
mp_agent_task_item     -- 逐条结果：taskId / contentId / field / oldValue / newValue /
                          confidence / reviewStatus(pending|accepted|rejected) / rejectReason

权限点：content:agent（发起任务）、content:agent_apply（采纳建议）。发起和采纳要分开——让编辑能发起、主编才能采纳，是个很自然的分工。

六、分期

期范围目标估算
第一期A1 导入质检 + B1 分类 + B2 标签 + B3 摘要SEO + 批量确认审核 UI把你现在这 6 篇（以及后续导入的几百篇）从"未分类草稿"变成可发布状态约 1 周
第二期A2 排版规范化 + A3 合规预检 + C1 一稿多态 + diff 审核 UI解决导入内容"不好看"和"不合规"约 1.5 周
第三期C2 选题初稿 + D1 商品挂载 + D2 效果复盘从"处理存量"转向"生产增量"，形成闭环约 2 周

强烈建议第一期就把留痕与回滚做进去，不要留到后面——它是后续所有提权的前提。

七、明确不做的事

  • 不做全自动发布（至少前三个月）。内容直接到用户面前的路径上必须有人。
  • 不做自主规划的 agent loop。当前场景是明确任务的批处理，任务式设计足够且可控；让它自己决定"接下来干什么"只会增加不可预测性。
  • 不做多 Agent 协作。一个角色一套提示词，够用很久。
  • 不做长期记忆。内容处理是无状态的，每次任务独立，反而更稳定。
  • 不追求一步到位的"全自动"。先让它把"未分类"这件事干利索，人对它有信心了，再谈更多授权。
本方案基于 2026-08-22 的代码实况设计：现有 Agent 为单例配置（mp_agent_config + 知识库 + 版本管理 + OpenAI 兼容调用），内容表字段（分类/标签/摘要/SEO/排版主题/置顶推荐/定时发布）均已具备，mp_content_product、mp_search_log、mp_analytics_event 可直接作为数据源。
