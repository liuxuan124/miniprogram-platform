运营中心 · 横向运营能力统一收口

基于现有后台菜单、路由表与库表的实测核查结果
日期：2026-10-05 当前迁移水位：V113 影响端：admin 后台 + backend（小程序端仅资源位子模块）

一、结论

方向成立，但实施口径须由「新建一个平台运营模块」调整为「收编已有能力 + 补真缺口」。 核查发现原清单中五项能力里，三项的后端底座已经建好，缺的只是后台界面； 只有「资源位运营」与「搜索运营」属全新建设。据此实施成本比原估计低，但若按原方案新建， 将与现有 /activity、/commerce/coupons、/content/creators 形成重复入口。

1.2 现状核查明细

  • 私域引流（最重要的一条修正）：mp_group_qrcode 具备 valid_until、sort_order、status 三个轮换字段，管理端 CRUD（AdminGroupQrcodeController，POST 已按 id 是否为 null 自动 upsert，无需补 PUT）、C 端取码接口（MpGroupQrcodeController）、以及每小时扫描过期码的定时任务（GroupQrcodeRotateJob）全部就绪。
    但小程序端从未调用过该接口——全仓检索 /api/v1/mp/group-qrcode 在 miniapp/ 下零命中；装修器组件 dsl-join-group 的群列表完全来自页面 DSL 内联配置（config.groups[].qrcode / wecom_url），组件内没有任何网络请求。CHANGELOG 亦已记录「mp_group_qrcode 仍 0 条，接口通了但运营数据未录，前台相关功能是空态」。
    结论：这是一套「造好了引擎但没接轮子」的半拉子工程。仅补后台页面而不接通 C 端，运营配置的活码在小程序上不会生效——「满员自动切码」永远不会触发。P0 的实施范围因此由「纯写页面」变更为「写页面 + 接通 C 端」。
  • 读者群已存在：mp_reader_group 的完整 CRUD（AdminMemberOpsController 的 /reader-groups 四个接口）与后台界面（admin/src/views/community/list.vue 底部「读者群」区块，含增删改、启停、到期标签）均已上线，收编即可，不重复建设。
  • 邀请裂变：mp_invite_relation、mp_invite_scene、mp_invite_content_unlock、mp_referral_commission 四张表齐全，MpInviteController 服务小程序端；后台无运营侧收口。
  • 活动管理：现有 /activity 为顶级菜单，页面 1292 行，语义是「沙龙 / 课程 / 展会的报名、审核、核销」（含核销中心），并非营销活动。原方案直接新增同名「活动管理」，将产生两套入口。
  • 审核中心：创作者申请审批链路已打通（AdminCreatorController + mp_creator_application）；AdminComplianceController 仅有 1 个只读接口 GET /audit-events；举报与封禁无表、无接口。
  • 搜索运营：小程序搜索页 pages/search 已存在（263 行），热门词常量 SEARCH_HOT 硬编码于 miniapp/data/warm-source.js，运营不可改。全站无底纹词、热词榜、搜索置顶干预接口。敏感词仅存在于内容审核链路（ContentAuditRulesService）。
  • 资源位运营：全库检索 popup / bulletin / announce / banner 零命中。现有 dsl-banner、dsl-promo-banner、dsl-float-button、dsl-notice-bar、dsl-flash-sale 等均为页面级 DSL 组件，只能随装修器发版，无跨页面全局触点。

二、边界规则

收口的前提是先定义「什么该进运营中心」。建议采用一条判据：

归属判据

资产 —— 页面、内容、商品、社区：长期存在、由各自模块维护其自身生命周期 → 留在原模块。

运营动作 —— 具备「时间窗、排期、启停、跨资产生效」四个特征之一的动作 → 归运营中心。

按此判据：卡券本身是资产（留在商业变现），但「发券活动」是运营动作；星球介绍页是资产，但「星球招新活动」是运营动作。这条规则决定了后续边界争议的处理方式，建议写入模块说明。

三、目录结构

建议一级目录命名为「运营中心」，置于「工作总览」之后。现有独立的 /activity 一级菜单收编为二级项，原路由保留重定向以兼容旧书签。

├── 工作总览 ├── 运营中心 （新增一级 · 横向运营动作） │ ├── 营销活动 收编现有 /activity + 新增营销活动类型 │ ├── 资源位运营 全站弹窗 / 开屏公告 / 悬浮挂件 │ ├── 搜索运营 底纹词 / 热门搜索词 / 搜索干预 │ ├── 私域引流 微信群活码 / 企微客服 / 导流漏斗 │ └── 审核中心 创作者入驻 / 内容人审 / 举报处理 ├── 小程序 ├── 内容管理 ├── 商业变现 ├── 用户管理 / 会员管理 / 社区管理 ├── 活动与预约 （原 /activity 保留，语义收窄为线下） │ ├── 线下活动 │ └── 预约管理 ├── 数据统计 / 经营管理 / 系统设置

原来

横向运营动作散落在各垂直模块：
弹窗只能进装修器改页面；
热词硬编码在小程序源码；
活码后端就绪但无界面；
活动管理实为线下报名；
审核只有创作者申请一处。

现在

一级目录「运营中心」统一收口五类横向动作，
运营按排期启停资源位与活动，无需装修器发版；
搜索词与底纹由后台下发；
活码轮换可视化维护；
审核队列集中处理。

四、分批实施

P0私域引流 + 搜索运营后端就绪 · 需同时接通 C 端

4.1 私域引流

本子模块拆成「后台补页面」与「C 端接线」两段，必须两段都做才算交付；只做前者等于给一张没有消费方的表配界面。

  • ① 后台页面：新增 admin/src/views/ops/private-domain.vue，含活码列表、新增/替换二维码、启停、排序、有效期与到期提醒、按群分组。 接口侧新增 admin/src/api/groupQrcode.ts 客户端（当前无任何 API 封装）。
  • ② C 端接线（关键）：改造 miniapp/components/dsl-join-group，将群列表来源由「页面 DSL 内联配置」改为「优先请求 GET /api/v1/mp/group-qrcode?groupKey=，失败或未配置时回落 DSL 内联值」。 回落策略必须保留，否则接口异常会导致加群组件整块空白。group_key 仍由装修器配置（与现有 config.groups[].id 对齐），二维码图片本身不再由运营手填。
  • ③ 收编读者群：community/list.vue 底部的读者群区块迁移至本页统一管理，避免「社区管理」与「运营中心」两处都能改群。
  • 后端：零改动（CRUD、取码、定时轮换均已完成；POST 已支持 upsert）。
  • 库表 / 迁移：无。
  • 发布影响：需小程序发版（dsl-join-group 在主包内，改动量小，但须走真机验证 + cli preview 包体复核）。

4.2 搜索运营

  • 页面：新增 admin/src/views/ops/search-ops.vue，含底纹词配置、热词排序、搜索干预、敏感词。
  • 后端：新增 AdminSearchOpsController，提供底纹词/热词/干预的读写；敏感词复用 ContentAuditRulesService，不新建词库。
  • 库表：新增 mp_search_keyword（热词与底纹）、mp_search_intervention（置顶干预）。
  • 迁移：V114__search_ops_config.sql。
  • 小程序端：pages/search/search.js 将 SEARCH_HOT 改为接口下发，保留本地兜底以防后端未升级时白屏。搜索页已在主包，增量极小。
P1营销活动收编 + 审核中心补齐以搬迁与补齐为主

4.3 营销活动（收编）

  • 页面：现有 admin/src/views/activity/index.vue 迁移为 ops/campaigns.vue，新增「营销活动」类型页签；原路径重定向。
  • 后端：复用 AdminActivityController，扩展活动类型枚举（打卡营 / 邀请裂变 / 促销会场 / 专题活动）。
  • 库表：mp_activity.type 扩枚举值，无需改结构。
  • 迁移：V115__campaign_type_enum.sql（如仅注释变更则并入 V114）。

4.4 审核中心

  • 页面：新增 admin/src/views/ops/moderation.vue，三类队列分页签：创作者入驻（已有）、内容人审（新）、举报处理（新）。

五、风险与约束

权限前缀不可落在 super_admin 专属域

SecurityConfig 仅做 hasRole 校验，mp_permission 只控制菜单显隐、不控制接口。现有 super_admin 专属前缀为 finance / agent / refunds / system / admin-users / roles / permissions。

运营中心面向 content_ops 开放，新增接口路径必须避开上述前缀，统一使用 /api/v1/admin/ops/**。历史上文件上传接口挂在 system 前缀下，导致 content_ops 全量 403。

主包预算只认 cli preview 的包体表格

P0 / P1 三项（活码、搜索配置、审核）对小程序主包几乎无增量，可先行。P2 资源位需在 app.js 挂载全局组件，属主包增量项，须单独立项并在构建后以 cli preview 实测为准，不得依据本地估算。

已建成但未接线的能力，须先接线再配界面

mp_group_qrcode 是典型样本：表、管理端 CRUD、C 端取码接口、每小时轮换定时任务一应俱全，唯独小程序端从未调用，装修器组件仍读内联二维码。 同类风险适用于全部子模块——动工前必须先确认「谁消费这份数据」，确认消费方存在再建界面，否则产出的是没有消费方的后台页。

核查方法：用接口路径（而非表名）在小程序源码中检索调用点；检索无命中即视为未接线。

命名冲突

「活动管理」名称已被 /activity 占用。新目录下应命名为「营销活动」，原模块语义收窄为「线下活动」，避免运营在两处入口间混淆。

菜单权限双边口径

新增菜单需同时在 router 的 meta.permissions 与后端菜单权限表登记。只写一侧会导致菜单可见但接口 403，或接口可用但菜单不显示。

迁移编号须双确认

并行会话可能抢占编号（INSERT IGNORE 会静默不生效）。动工前须同时执行：本地 ls migration | grep -E "^V1[0-9][0-9]__" | sort -V 与线上 SELECT version, script FROM schema_version ORDER BY 1 DESC LIMIT 5，比对 script 名而非仅版本号。本文所列 V114–V117 为规划号，落地时需重新核实。
