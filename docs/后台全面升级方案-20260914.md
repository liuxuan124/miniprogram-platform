# 后台全面升级方案（视觉 / 命名 / 流程 / 分享）

日期：2026-09-14  
范围：`admin/`（72 页 / 82 路由）、`backend/`、`miniapp/`  
决策前提：配色采用**方案 A 克莱因蓝专业型**，侧栏改浅色，先试点再铺开（原型见 `prototypes/admin-theme.html`）

### 已确认决策（2026-09-14）

1. 小程序端「知识库」**保留原名**（指商品列表）；后台 AI 侧改名为「AI 语料库」以解撞名
2. 期次按本文档顺序执行：视觉 → 命名/IA → 流程 → 分享 → 收尾
3. 路由迁移**不保留兼容 redirect**，直接改干净（系统仅内部使用）

## 0. 体检结论

四条主线，问题按严重度排序：

| 维度 | 现状 | 根因 |
|---|---|---|
| 命名 | 同一概念最多 5 种叫法，小程序「知识库」= 后台「商品」，AI「知识库」又是第三件事 | 无术语表，各期功能各自命名 |
| 流程 | 配完整会员体系跨 ≥5 页；小程序发布有「上线/草稿/版本/还原点/DSL」5 套并存概念 | 功能按模块堆叠，无任务导向串联 |
| 视觉 | 2433 处硬编码颜色、484 个色值、586 处硬编码字号、10 种圆角；`.surface-card` 定义了但 0 页使用 | 设计 token 有定义无约束 |
| 分享 | 后台可配分享标题/图，小程序运行时**不读**；无小程序码/海报；邀请奖励 `reward_status` 永不更新 | 配置层与运行层未接线，增长闭环未产品化 |

数据表也有遗留污染：`sys_user`、`` `user` ``、`mp_booking_*` 三套废表，`User` 与 `MiniProgramUser` 双实体映射同一张 `mp_user`。

## 2. 视觉层重构

### 2.1 主题收口（1 个文件）

删除 `admin/src/styles/tokens.css`，只保留 `admin/src/assets/styles/theme.css`，内容为方案 A 的完整令牌：

- 主色 9 阶由 `#002FA7` 同色相（222°）派生：`--brand-50 … --brand-900`，`--brand = --brand-700`
- 冷中性 8 阶：`--n-0/25/50/100/200/300/500/700/900`
- 语义色：`success #0E9F6E` / `warning #B45309` / `danger #D92D20` + 各自 soft 底
- 尺度：字号 4 档、间距 6 档、圆角 3 档（**删掉现有 10 种圆角，只留 6/8/12**）
- Element Plus 变量全部桥接到上述令牌

### 2.2 禁止再写死样式（关键，否则半年后回到原点）

新增 stylelint 规则，对 `admin/src/views/**` 生效：

- 禁止 hex / rgb 字面量（只允许 `var(--*)`）
- 禁止裸 `font-size: Npx`（改用语义类或 `var(--font-*)`）
- `border-radius` 仅允许三档令牌

### 2.3 五个布局组件（页面不再自写骨架）

| 组件 | 职责 | 硬约束 |
|---|---|---|
| `PageHeader` | 标题 / 描述 / 右侧操作区 | **全页唯一 primary 按钮位** |
| `FilterBar` | 筛选项 + 重置/查询 + 超过 4 项自动折叠 | 查询按钮不得为 primary |
| `PageCard` | 卡片容器 | 只有 1 档边框 1 档圆角 |
| `DataTable` | 分页 / 加载 / 空态 / 批量栏 / 导出 | 行内操作统一 text 按钮 |
| `FormSection` | 表单分节 + 完成度 | 节标题序号自动生成 |

配套：指标区改开放式排版（如原型中的 148/23/31/12 横排），不再人人一张卡。

### 2.4 试点顺序

工作台 → 内容列表 → 星球配置。三页验收通过后，按「列表页批量替换 → 表单页逐个替换」铺开。

## 4. 流程重构（按影响排序，8 项）

### P0-1　小程序发布：5 套概念砍到 3 个

现状「上线 / 保存草稿 / 保存版本 / 还原点 / 上传代码」并存，运营经常误进「版本」页。

统一为三态：**草稿 → 已上线 → 历史版本**。具体：
- 外观页的「草稿记录/还原点」与页面的「历史版本」合并为同一个「历史版本」概念
- 「保存版本」改叫「存档当前状态」，与「上线」在同一页面同一区域，文案写明区别
- 「上传代码」独立为「小程序发版」，明确它是微信侧动作，不与页面上线混排
- 「导入/查看 DSL」收进「高级」抽屉，默认不可见

### P0-2　会员权益：文本框改勾选器

`member/level.vue` 的「权益描述」是自由文本，后端只认 `MemberBenefitCodes` 里的固定码，运营填「95折」完全不生效。改为权益码多选 + 参数输入（折扣率、积分倍率），描述文案由所选权益自动生成，并在等级列表显示「已生效/仅展示」标记。

### P0-3　会员体系配置向导（跨 5 页 → 1 页）

在 `/member/planet` 增加「会员体系向导」：等级 → 套餐 → 星球可见范围 → 内容标记 → 模块开关，五步在同一页完成，每步显示当前状态与跳转。同时修掉三个断点：
- 商品分类允许勾选 `membership`（`product/category.vue:116`）
- 商品列表筛选加「会员套餐」（`product/index.vue:46`）
- 删掉从星球跳转时硬编码 `category_id = 2`（`product/edit.vue:1467`），改为按 `allowed_product_types` 自动匹配

### P0-4　内容编辑加防丢失

商品编辑和装修器都有自动保存 + 离开提醒，内容编辑（15+ 字段）两者都没有，且保存后强制跳回列表。补齐 5s debounce 自动保存 + `beforeunload` + 路由守卫；保存后留在原页并提示，「返回列表」作为显式操作。

### P1-5　内容分类的隐藏依赖

分类不「发布到顶栏」就不出现在发文下拉里，新手会卡住。改为：发文下拉显示全部分类，未发布的标注「未上架，发布后 C 端不可见」并提供一键上架。分类的双入口（列表内弹窗 + `/content/category`）保留列表内弹窗为主，独立页改为跳转。

### P1-6　功能开关一致性

`order` 开关目前完全无效（订单菜单跟 `product` 走），`comment` 有开关有路由但无菜单。逐个校准 12 个开关的「菜单可见性 + 小程序表现 + 后端 Guard」三方一致，并统一前端 store 默认值与 `basic.vue` UI 默认值（现在商品一个默认开一个默认关）。

### P1-7　评论审核接入内容流

内容列表每行增加评论数与「审核」直达链接，评论审核页加入「内容运营」菜单。

### P2-8　系统设置拆分

`basic.vue` 2342 行承担 5 个 Tab（基础/模块/物流/权限/订阅），拆为 `/system/basic`、`/system/modules`、`/system/logistics`、`/system/roles`、`/system/subscribe` 五页。模块开关切换增加二次确认（当前切换即保存，误点直接影响 C 端）。

## 5. 分享功能升级（当前最弱环节）

### 5.1 现状定位

有「全局分享兜底 + inviterId 归因」的地基，但三处断裂：

1. **配置不生效**：`miniappShareTitle` / `miniappShareImage`（`system/basic.vue`）和页面 DSL 的 `share_title` / `share_image` 后台都能配，小程序运行时不读，仍用 `share.js:37-49` 的硬编码标题表
2. **归因漏斗**：6 个详情页（content/product/moment/question/detail×2）自定义了 `onShareAppMessage` 但绕过 `buildSharePath`，分享出去**不带 inviterId**，这几个页恰恰是分享最多的
3. **无产品化增长**：无小程序码、无分享海报、无邀请页；营销「邀请好友」是占位；`mp_invite_relation.reward_status` 建表后永远是 `pending`；埋点无 `share` 事件，看板无分享数据

### 5.2 P0：接线（工作量小，收益立刻可见）

| 改动 | 位置 |
|---|---|
| `share.js` 优先读后台配置，硬编码表降为最后兜底 | `miniapp/utils/share.js:19-49` |
| DSL 页把 `share_title`/`share_image` 写入页面分享配置 | `miniapp/utils/render.js:328` 已解析，补 setData |
| 6 个详情页自定义分享改为走 `buildSharePath` | 见 §5.1 第 2 点各页 |
| 补 `share` 埋点事件（分享发起 + 分享落地） | 复用 `/api/v1/mp/events` |
| 后台分享配置入口从 basic.vue 抽到独立「分享设置」 | 新页 `/system/share` |

### 5.3 P1：产品化

- **小程序码生成**：后端接 `getwxacodeunlimit`，支持带 scene 的渠道码/邀请码；后台可为页面/商品/星球一键生成并下载
- **分享海报**：小程序侧 canvas 合成（封面 + 标题 + 小程序码 + 邀请人昵称），详情页「生成海报」按钮
- **邀请页**：小程序 `pkg-user/invite`，展示邀请码、已邀人数、奖励进度；后台「邀请好友」占位页替换为真实配置（奖励类型、额度、上限）
- **统一 scene 路由器**：现在 `inviterId`、`sourceChannel`、内容 ID 三处各自解析 scene，合并为一个入口

### 5.4 P2：闭环与看板

- 邀请奖励真正发放：`reward_status` 状态机（pending → granted → 失败原因），支持积分 / 优惠券 / 会员天数三种奖励
- 被邀请人也给奖励（现在只有邀请人拿 10 积分）
- 分享看板：分享次数、分享带来访问 / 注册 / 付费，按页面和渠道拆分；接入「经营分析」页漏斗，补 share 步骤

## 7. 风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 路由不留兼容，改漏一处即白屏 | 高 | 迁移后全量 grep 旧路径字面量；逐路由点击走查一遍；`router` 加 404 兜底日志 |
| 主题令牌替换时页面样式错乱 | 中 | 先只新增 `theme.css` 并保留旧变量别名，试点三页验证后再删旧文件 |
| stylelint 规则导致大量报错阻塞开发 | 中 | 规则先只对新增/改动文件生效（lint-staged），不做全量强制 |
| 删除 4 个 orphan 页面误删仍被引用的 | 低 | 删前 grep 组件名与路径确认零引用 |
| 数据表清理误删线上数据 | 高 | 只改名为 `_deprecated_` 前缀，观察一个版本再删；操作前 dump 备份 |
| 分享改造影响已上线小程序 | 中 | 分享配置读取做兜底链（后台配置 → 实体字段 → 硬编码），任一层缺失不报错 |
| 会员权益改勾选器，已有自由文本数据丢失 | 中 | 迁移脚本把原文本存入 `benefits_legacy_note` 字段保留展示 |
